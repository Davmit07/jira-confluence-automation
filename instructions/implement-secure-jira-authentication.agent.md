- **Input format:** Accept Jira Cloud connection settings from the existing `ATLASSIAN_BASE_URL` and `ATLASSIAN_EMAIL` configuration values, plus `JIRA_TOKEN` supplied locally through environment variables or an approved secret manager. Use `JIRA_PROJECT_KEY` only as project configuration, never as a credential.
- **Input constraints:** Do not add credentials to source code, command-line arguments, committed configuration, workbooks, reports, fixtures, or logs. Keep `.env` local and ignored by Git; `.env.example` may contain variable names and safe placeholders only.
- **Processing:** Read credentials at runtime from the approved local configuration source; do not use hard-coded defaults or silently fall back to anonymous access or another credential source.
- **Processing:** Validate that all required values are present, the Jira base URL is an absolute HTTPS URL with a hostname and no embedded username/password, and the configured email and token are non-empty. Fail before making a network request if configuration is invalid.
- **Processing:** Use Jira Cloud email plus API token with HTTP Basic authentication over HTTPS. Build authorization headers only in the HTTP client/request layer; never print, return, or include them in exception messages.
- **Processing:** Send credentials only to the configured Jira origin. Disable or explicitly guard cross-origin redirects so credentials cannot be forwarded to an untrusted host.
- **Processing:** Reuse the project's existing HTTP client and configuration patterns where possible. Keep authentication separate from Jira retrieval logic so the client can be tested with mocked requests.
- **Processing:** Surface missing/invalid configuration, authentication denial, and network failures as explicit actionable errors without exposing token values, encoded credentials, request headers, or secret-bearing response details.
- **Output format:** Provide a configured Jira client or request-auth configuration to the caller, without exposing the raw token or authorization header in the public result. On failure, return/raise a typed or otherwise repository-consistent error that identifies the failure category and safe remediation.
- **Output constraints:** Never log secrets, authorization headers, full credential-bearing request objects, or unredacted exceptions that may contain them. Do not place real credentials in tests; use dummy values and mocked HTTP requests.
- **Output constraints:** Add tests for missing credentials, invalid/non-HTTPS URLs, successful auth-header construction without logging, unauthorized responses, network errors, and cross-origin redirect handling. The default test suite must not contact live Jira or require credentials.
- **Output constraints:** Document the required local variables and approved secret source without publishing real values; preserve Jira's read-only project scope and do not add Jira write operations as part of authentication.
